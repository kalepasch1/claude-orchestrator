# Orchestration Pipeline Contract (Refined)

## Overview

This spec reconciles two prior **orchestration pipeline implementations** (beethoven deployfix and smarter qafix) into a single contract for deploying backlog work using **native-claim source type** with model-adaptive task routing.

**Key decision:** This is an operator drop-box task, not a manual serial session.
- Route as: `intake/processed/PROMPT-orchestration-pipeline-contract.md`
- Intake will decompose via `planner.py` contract-first DAG
- Execution queued to parallel agents via `prompt_factory.py`

---

## Task Definition

### Scope (Resolved Ambiguities)

**"Full backlog"** = All open PR/branch items in both projects that match the source type (`native-claim`) and task class filters, grouped by priority and risk:
- **beethoven project**: `deployfix` branches (build tasks, need=6, risk=standard)
- **smarter project**: `qafix` branches (plan tasks, need=8, risk=strategy)

**"keepalive-single-supervisor"** = Deployment supervision mode:
- Single operator monitors execution state via `fleet_control.py` heartbeat
- Config synced to fleet via centralized `fleet_config` table (safe keys only, no secrets)
- Fail-soft error handling: errors logged but do not wedge runners

**"dropbox-mission-complete"** = Status flag to emit when:
- All backlog items have been triaged → planned → routed to agentic coders
- All model assignments confirmed and pinned to config
- All required approval gates passed (see Acceptance Criteria below)
- Ready for phased deployment (no rollback required at this phase)

**"native-claim" source type** = Work originating from internal integration points (not external APIs):
- Generated by `intake_watcher.py` from canonical-format intake files
- Includes encoded recovery-intent metadata (branch naming, commit structure)
- Routable via `fleet_config` to model-adaptive pipelines

**Task classes & metrics:**
- **build** (need=6, risk=standard): Minimal uncertainty, 6-token preflight budget, model: google:gemini-2.5-flash
- **plan** (need=8, risk=strategy): Higher uncertainty, 8-token strategic planning budget, model: local:deepseek-coder-v2:16b
- **QPD leader metrics** (q=6.2, q=7.42, etc.): Quality Performance Density scores — higher q = more confident; used to select agentic coder model; n=count of prior similar tasks

## Acceptance Criteria

### Deployment Success (All Required)

1. **Backlog Item Processing**
   - [ ] All `native-claim` PRs/branches in both projects triaged (preflight triage completed)
   - [ ] Each item assigned to correct model based on task class
   - [ ] No items remain in "unclassified" state in `fleet_config` table

2. **Model Pipeline Pinning**
   - [ ] Preflight triage model confirmed: `google:gemini-2.5-flash` for build tasks, `local:deepseek-coder-v2:16b` for plan tasks
   - [ ] Strategy planner model assignments match QPD leader selections (q≥6.2 for build, q≥7.4 for plan)
   - [ ] Agentic coder fallback paths configured (ollama for beethoven, claude for smarter)
   - [ ] All model assignments persisted to `fleet_config` (keys prefixed `ORCH_`)

3. **Approval & Gate Management**
   - [ ] All backlog PRs reviewed and approved (code-review passed or auto-approved per policy)
   - [ ] No blocker issues (security, lint, test failure) in any item
   - [ ] Merge train eligibility confirmed for all items

4. **Supervision & Monitoring**
   - [ ] Keepalive heartbeat configured in `fleet_control.py` (single-supervisor mode)
   - [ ] Fleet-wide config changes applied; all runners report healthy
   - [ ] No errors logged in fail-soft paths for ≥5 min baseline

5. **Versioning & Handoff**
   - [ ] All worktrees isolated under `{repo}-wt/{slug}`; no in-place checkouts in main repos
   - [ ] All commits authored as `kalepasch1 <kalepasch@gmail.com>`
   - [ ] Branches persist as `agent/{slug}` for merge-train pickup
   - [ ] Result tag: `DEPLOYED-PIPELINE-{date}-{orchestration-run-id}` pushed to each project

### Rollback Criteria & Procedure (If Needed)

- **Trigger:** Any fleet runner heartbeat missing for >91 seconds, or >10% of items in merge-queue state with no progress
- **Procedure:**
  1. Query `fleet_config` for last-applied version
  2. Revert `ORCH_*` config keys to prior snapshot in DB (do not touch git)
  3. Force-refresh fleet via `fleet_control.py reset-config` command
  4. Verify all runners report ALIVE before resuming
  5. Do NOT merge any PRs until fleet is verified healthy again

## Deployment Phases

1. **Prepare** (Intake decomposition)
   - Intake watcher auto-routes this spec via `prompt_factory.py`
   - Parallel agents: preflight triage all backlog items
   - Decision point: Any blockers? → Route to remediation or proceed.

2. **Assign** (Model pinning)
   - Strategy planners generate execution DAG per item
   - QPD leader metrics confirm model assignments
   - Config pushed to fleet_config table; all runners ack

3. **Deploy** (Agentic coding)
   - Agentic coders execute per DAG; fail-soft errors logged
   - Keepalive supervisor monitors heartbeat; no rollback needed unless >91s gap
   - Worktrees pushed; agent/* branches persist

4. **Verify** (Post-deployment)
   - Vercel deployments confirm 200 OK
   - Manual spot-check of high-risk items (plan tasks in smarter)
   - Tag result: `DEPLOYED-PIPELINE-{date}` on merge commit

5. **Handoff** (Merge train pickup)
   - All agent/* branches ready for merge-train
   - Status flag: `dropbox-mission-complete` logged
   - Operator confirms via status dashboard

## Rationale (Convention-Based Decisions)

1. **Dropbox routing (not manual session):** Spec is strategic/operator-level → CLAUDE.md convention says use intake drop-box, not serial sessions. Serial reserved for fleet-down recovery only.

2. **Single-supervisor keepalive:** Matches "fail-soft error handling" convention — errors logged, do not wedge. Heartbeat is the signal.

3. **Config table + git sync:** CLAUDE.md pattern: code via git (agent/* branches), config via DB (fleet_config), coordination via heartbeat.

4. **Worktree isolation:** CLAUDE.md sentinel.py monitors main checkout; all agent work in `{repo}-wt/{slug}`. Prevents contamination.

5. **Commit author pinning:** CLAUDE.md requires `kalepasch1 <kalepasch@gmail.com>` for Vercel deployments to succeed (production blocks other authors).

6. **Fail-soft not silent:** Corrected convention (from memory): broad `except Exception` is OK **if logged**. Silent swallows are defects.

7. **Model assignment precedent:** Use QPD leader metrics (q-score) and prior similar task count (n) to select; config pinning makes it tunable fleet-wide.
