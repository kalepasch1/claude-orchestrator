This is deliberately a tool rather than a one-off scan. The namespace is
unbounded and regrows, so the reconciliation has to be repeatable:

```
python3 runner/tools/reconcile_orch_rescue.py --repo . --base origin/master
```

Two design points worth keeping:

- **Verdicts are memoised by patch-id.** 532 refs collapse to 404 distinct
  swept deltas; the same uncommitted tree is captured on every tick.
- **Blob genealogy comes from one `rev-list --objects` pass** rather than
  `rev-list <base> -- <path>` per file. The per-file walk is correct but costs a
  process per commit per file; it ran for over 15 minutes without finishing.
  The index build takes about two seconds. `test_prebuilt_index_matches_lazy_lookup`
  pins the two paths to the same answer so the speedup can't silently drift.

## Reading the conflicts honestly

`CONFLICTED_NEEDS_FOCUSED_TASK` here means: the swept blob never appeared at that
path on `origin/master`, but the path exists there with different content. That
is **not** the same as lost work. Master may have solved the same problem
differently, in which case the sweep is a dead end. The classifier refuses to
guess, which is why nothing was auto-applied from this namespace.
