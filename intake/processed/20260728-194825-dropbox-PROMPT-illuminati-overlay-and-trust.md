## Phase 2.5 — The live sidecar, graded option ladder, and fork-node decisioning (strategy Part 4.5)
This is the core differentiator — build it fully.
1. **Live sidecar** during coding (vibe or autonomous), rendered THREE ways from one data stream: a hosted web panel, a terminal TUI (for our terminal + any shell), and an IDE webview (VS Code first). It shows Tier-1 inline scores as code is written, then the deep pass posts the option ladder. Must run alongside whatever the vendor's own UI is (we host, or ChatGPT/Cursor/Copilot/Codex host) — the sidecar is additive, never blocking the editor.
2. **Graded option ladder**: for any regulatory/compliance decision point, present 5-7 standard options ordered on a risk gradient scored by CADE + the Vigil exam engines + the swarms (via S2S to the combined Apparently stack). Each option carries: the AUTHORITY CHAIN from the omniscience corpus (the specific NAL/enforcement/rule, with precedential weight — e.g., "NAL explicitly permits → low"; "recent isolated enforcement, distinguishable → elevated"), a residual-risk score, a generated code diff, any required/available regulatory filings, and actions: **Adopt** (apply diff), **File** (autonomously initiate the Apparently filing/license/regulatory submission for this option via S2S), **Escalate** (open the multi-department decision in repurposed Smarter).
3. **Side-prompt sessions**: attach a full-reasoning chat to any option to dig deeper or generate NEW options (same CADE + corpus intelligence); generated options join the ladder, attributed in steering_events.
4. **Fork-node / never-stop-production**: adopting an option that touches gated territory creates a decision node scoped ONLY to the affected files/contract — the orchestrator quarantines just that slice (a DECISION_PENDING branch/worktree; coordinate with the beethoven review-gate wave's merge-train + steering_events), the rest of the DAG keeps building, and only the affected component holds for approvals. Non-impacted dev never stops. On approval-of-final-iteration, the node merges normally.
5. **Multi-department routing** = repurposed Smarter in Apparently: material choices (per configured thresholds + the constitution) route to cross-departmental approvals/inputs/revisions — lawyers, strategy, finance shape the code in their own vocabulary; every input is a first-class attributed steering_event. Everything stays bounded by the tenant constitution.
6. **Off-editor data capture**: if the user codes outside our terminal (any vendor), all sidecar decisions/telemetry still sync to Apparently — data flows in regardless of where code is written; cross-promote into Apparently for the multi-department/flexibility features they'd unlock by coming onto the platform terminal.
- Proof: option ladder returns 5-7 graded options with authority chains from a fixture corpus; fork-node quarantines only affected files while a second task on unaffected files proceeds (integration test with the orchestrator merge-train); File action triggers a mocked Apparently filing; side-prompt appends an attributed option.

- Bind every compliance-policy clause to observable evidence (code patterns via interception + the code-binding analyzer; email behavior via the findings pipeline; filing status via Apparently). Controls become a shared versioned library; exam-pass data (merged Vigil) ranks controls → propagation priority.
- Proof: drift in both directions produces the right artifact; a released control generates a policy update + a code PR for a second fixture tenant; propagation respects contributor discretion + approval gates.
