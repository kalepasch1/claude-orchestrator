- A management-toggleable phase in EVERY production pipeline (code builds, self-service features, legal/financial documents, marketing assets), after functional approvals, before release:
  (a) Product/design adjust end-state UI/UX, formatting, text, imagery, graphics, in-app animations — using the standard option-ladder + side-prompt + approval machinery.
  (b) SECONDARY COMPLIANCE PASS on the designed artifact itself: a second Illuminati/Bench review of text, images, displays, graphics, and ANIMATIONS under the identical risk-gradient/advisory/approval/steering structure as code (promo-compliance engines are the backbone; add claims-substantiation, required-disclosure, and dark-pattern/animation checks). Auto-flag when the marketing layer carries additional regulatory implications beyond the product's own score.
  (c) Rapid-review UX per the Tomorrow negotiation pattern: full-app view + zoom-to-component, diffed against pre-design state, superintelligence annotations per change (what/why/risk).
  (d) Final combined gate: approve "full app + this component" together; release proceeds; per-pipeline/per-tenant toggle. Works seamlessly with code reviews (shared steering_events + approvals + fork-node mechanics).
  (e) Telemetry: log every design adjustment to train a predictive design pass (pre-apply known team preferences over time).
- Proof: a fixture build traverses functional approval → design adjustments → secondary compliance pass (a seeded non-compliant animation is flagged at the right gradient) → combined full+component approval → release; toggle off skips the phase; telemetry rows written.
