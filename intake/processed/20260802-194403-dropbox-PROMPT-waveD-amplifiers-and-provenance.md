## D1 — SELF-EXTENDING REQUIREMENTS ONTOLOGY (amplifies Wave A / apparently)
Diff-watcher on official application forms, statutes, and rules per jurisdiction: when a source
changes, auto-propose ontology updates (new/removed/altered requirement items) into a review
queue, then RECOMPUTE EVERY CLIENT'S READINESS overnight and notify only those whose readiness
or time-to-ready actually moved. The map maintains itself; clients learn about rule changes from
us before the trade press. Material ontology changes route to human approval; trivial auto-apply,
versioned, each citing the source diff.

## D2 — READINESS AS A BALANCE-SHEET ASSET (amplifies Wave A)
Quantify option value of readiness: a client 100% ready in N jurisdictions can enter any of them
in days rather than months — compute and display that option value (entry speed x market size x
probability of entry), track it over time, and expose the TIMING risk it implies to Tomorrow so
entry-timing can be hedged (Adaptive Perpetual Line eligible). Readiness stops being a checklist
and becomes a balance-sheet item clients defend.

## D3 — ADVERSARIAL CO-EVOLUTION / RED HIVE (amplifies Wave B1 / illuminati)
A permanent RED HIVE whose fitness function is DEFEATING our own recommendations — regulator-side,
competitor-side, and plaintiff-side swarms optimized to kill each option (find the enforcement
theory, the complaint, the competitive counter). No option ships until it survives the red hive;
both hives improve against each other indefinitely (co-evolutionary arms race, budget-capped,
red-hive findings become corpus precedent + red-team chips on the gradient card).

## D4 — STRATEGY MEMORY AS A MARKET (amplifies Wave B1)
Every deployed strategy's REAL outcome (approved / denied / enforced / ignored / market result)
prices the personas and chambers that backed it — routing weight and seating priority re-weight
on money-real results, not debate quality. Publish per-persona P&L-style records internally; the
hive's composition becomes continuously re-selected by outcomes (think trading desk, not think
tank). Includes counterfactual crediting (options NOT taken are scored when the world reveals
the answer).

## D5 — CORPUS AS INFRASTRUCTURE (amplifies Wave B2 / apparently-law)
Offer agencies a hosted, free "interpretive FAQ / guidance publication" surface: they publish an
answer ONCE through us, the whole industry reads it, canonical and citable, with their branding
and full editorial control. We become infrastructure regulators RELY ON rather than a party
mining them — the single strongest relationship + moat move available. Build: publication
workspace, agency-controlled editing, versioning, public read surface, subscription/alerts for
industry, and automatic ingestion into our canon the moment an agency publishes.

## D6 — INQUIRY-OUTCOME PREDICTION (amplifies Wave B2)
Before drafting, predict per candidate question: probability of an answer, expected content,
usefulness if answered, and RELATIONSHIP COST. Spend the scarce cadence budget only on questions
whose expected corpus value clears a bar; learn from every actual outcome (answered/ignored/
deflected) per agency and per question type. Agency goodwill becomes an explicitly optimized,
measured resource.

## D7 — DELTA MATRIX AS A DAY-ONE PRODUCT (amplifies Wave B2)
The cross-jurisdictional comparative-requirements matrix from 8B.1 ships as a product BEFORE any
agency replies: searchable comparison surface, per-topic "who requires what" views, export, and a
premium tier. Part 8B pays for itself immediately and seeds inbound interest from both industry
and agencies.

## D8 — OUTCOME-LEVEL INTEGRATION (amplifies Wave C / pipeline)
Extend initiative-level integration to OUTCOME-level: an initiative is not "done" until its
user-visible ACCEPTANCE MARKERS verify live in production (deploy-fingerprint check becomes the
definition of done). Every SLO, dashboard, and remediation bot inherits this definition — the
fleet optimizes for shipped capability, never merged code.

## D9 — DECISION-PROVENANCE GRAPH (cross-cutting; the keystone)
One graph spanning every app: each deployed code change, filed application, published memo,
approved policy, and hedged position traces back through the tribunal decision that authorized
it, the guidance answer that informed it, and the legal authority that justified it. Queryable
both directions ("why does this code exist?" / "what did this guidance answer change?"). This is
simultaneously: the examiner's dream artifact, the client's switching cost, the marketing proof
of rigor, and the training substrate that makes every future decision faster. Build on the
existing proof/attestation patterns (content-addressed, signed, offline-verifiable); every
Foulkon decision, guidance answer, and merge already emits the edges — this assembles them.
